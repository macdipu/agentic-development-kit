Software delivery for coding agents, with evidence and approval gates

The kit gives your coding agent 35 specialist skills, SDLC workflows, and a local Python harness. Work moves from request to release, and every step leaves a record. The harness blocks tool calls the active task hasn't been permitted to make.

Why

A process for agents to follow, and a record of what they did

A coding agent will write code as soon as you ask. The kit makes it read the existing context first, reuse what the project already has, and stop for a human decision where one is required.

Context before code

Agents read agentic/data/project-context/ first. They refresh only the stale or missing module and never re-audit the whole repository for each task.

Explicit human gates

Approval is never inferred. Release and UAT gates need an explicit decision tied to the scope revision. Only technical gates can be auto-approved.

End-to-end traceability

Each step links to the one before it: request, requirements, design, tasks, implementation, QA, release. Commits carry Work-Item, Task and Run trailers.

Minimum useful lifecycle

A work item gets the planning level it needs: Epic/Story/Task, Story/Task, Task-only, or execute-existing. Full sprint planning happens only when it's needed.

Resume anywhere

Run state, handoff notes and session records live in git-tracked .agent/. After a git pull, another machine or another agent picks up the run where it stopped.

Greenfield or brownfield

Project type is set per work item. New features run the full lifecycle. Changes to existing code start from the code, tests and data already there, and recover a baseline only where one is missing.

How it works

One path from prompt to release

A prompt or a document (FEATURE.md, CR.md, BUG.md, HOTFIX.md) becomes a canonical work item. The orchestrator then picks the next skill from the work type, stage, context, impact, policy and approvals.

Workflows

greenfield, brownfield, new-feature, change-request, bug-hotfix, sprint-planning, all dispatched through routing.md.

Routing cache

Route decisions are cached per work type, project type and module. A cache hit on the current kit version skips re-reading the workflow, persona and skill docs.

Result contract

Every specialist returns the same handoff shape: status, evidence and blockers. The harness checks that shape before the run moves to the next stage.

Skill catalog

35 specialists, one per job

Each skill is a SHA-256-pinned instruction file with its stage eligibility declared. The orchestrator uses a skill only in the stages where it applies.

Local harness

Workflow rules the harness enforces

A pure-Python runtime owns workflow state, approvals, context freshness, budgets, checkpoints and timing. The agent's own judgment doesn't override any of these.

PreToolUse gate

In Claude Code, native Bash, Write, Edit and NotebookEdit calls are checked against the active task's permissions. Bash commands must match the allowlist on their full argument list.

Budgets and timing

The harness limits attempts per scope, stage and skill, tool calls per task, and elapsed time per task. It records start, end, failure and interruption events, which you can query with timing RUN_ID.

Atomic run ledger

Each run is one JSON file. The run, its checkpoint and its audit entries are committed together with write-temp plus atomic replace, under a per-run lock.

Session hooks

SessionStart reports unfinished work and shows the pickup note. PreCompact saves a checkpoint. Stop writes the handoff and a session record.

Get started

Install in one command

The installer stages and validates the whole kit before it replaces any host file. Text outside the kit's marked section of AGENTS.md and CLAUDE.md is left as it was, and so are unrelated settings.

instruction-only default

Installs the workflow instructions, skills, templates and configuration.

  • No tool interception
  • No workflow state
  • Works with any agent

local-harness enforced

Also sets up workflow state and the runtime ledger.

  • Native Claude Code hooks (--agent claude)
  • CLI task protocol for Codex and other agents
  • doctor checks the install
install.sh
# from a reviewed checkout of the kit
$ git clone https://github.com/macdipu/agentic-development-kit.git
$ cd agentic-development-kit

# install into your project (brownfield | greenfield)
$ python3 agentic/kit/scripts/init_project.py \
    --target /path/to/project --project my-project \
    --type brownfield --mode local-harness --agent claude

# verify from the host root
$ python3 agentic/kit/runtime/python/agentic_runtime/cli.py doctor
$ sh agentic/kit/scripts/validate-kit.sh

Requires Python 3.10+ and nothing outside the standard library. CI runs on Linux and macOS with Python 3.10 and 3.13. Read the adoption guide before installing.

Boundaries

What the harness doesn't do

The harness is a local trust boundary for trusted adapters. Shared autonomous execution needs more infrastructure on top of it.

AreaImplemented locallyBoundary
ApprovalsDecisions tied to the scope revision, with evidence prerequisites and revocation--by is the operator's own claim. There is no authenticated identity or RBAC
ContextHashes of scoped files detect edits and deletionsThe caller chooses the files. Dependencies are not discovered automatically
ToolsExplicit permissions, side-effect classes, idempotency, auditHandlers are trusted. There is no OS-level isolation
PersistenceAtomic per-run JSON files with a lockOperators can write to it, so it isn't immutable audit storage. The lock covers one machine only
ProductionNo production stage and no L7 toolsNot supported on purpose

The full capability matrix is in the runtime guide.
